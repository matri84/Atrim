Atrim.

یک فریم‌ورک سبک، ساده و قدرتمند PHP برای ساخت ایده‌های بزرگ — مخصوص توسعه‌دهندگان فارسی‌زبان

PHP 8+ PDO RTL Ready Zero Dependency
↓ دانلود آخرین نسخه Atrim

۱. معرفی

Atrim یک فریم‌ورک سبک و مینیمال PHP است که بدون وابستگی خارجی (Zero Dependency) طراحی شده. هدف آن فراهم کردن ساختار تمیز، مسیریابی ساده، اعتبارسنجی قدرتمند، کار راحت با دیتابیس و سشن است تا بتوانید سریع‌تر پروژه‌های وب خود را بسازید.

✨ ویژگی‌های کلیدی
  • نصب‌کننده تعاملی (Installer) که کل پروژه را از صفر می‌سازد
  • سیستم Routing ساده با پشتیبانی از پارامترهای داینامیک
  • کلاس اعتبارسنجی کامل (مشابه Laravel) با پیام‌های فارسی
  • کلاس دیتابیس امن با PDO و متدهای آماده (CRUD + Pagination + Search)
  • مدیریت سشن با قابلیت انقضا
  • کمک‌کننده‌های فایل، URL، Redirect و Escape
  • پشتیبانی کامل از RTL و زبان فارسی

۲. نصب و راه‌اندازی

برای ایجاد یک پروژه جدید، فایل installer را در ریشه وب‌سرور (مثلاً htdocs یا www) قرار دهید و از طریق ترمینال اجرا کنید:

Terminal 
php installer

بعد از اجرا، نصب‌کننده به ترتیب اطلاعات زیر را از شما می‌پرسد:

سؤال مقدار پیش‌فرض توضیح
Enter Project Name Atrim نام پوشه و پروژه (فقط حروف انگلیسی، عدد، خط تیره و زیرخط)
Enter DataBase Host localhost آدرس سرور دیتابیس
Enter DataBase Name test نام دیتابیس
Enter DataBase Username root نام کاربری دیتابیس
Enter DataBase Password (خالی) رمز عبور دیتابیس
⚠ نکات مهم هنگام نصب
  • تا زمانی که پیام موفقیت نمایش داده نشده، ترمینال را نبندید و Ctrl + C نزنید.
  • نام پروژه نمی‌تواند خالی باشد و فقط کاراکترهای مجاز (a-z A-Z 0-9 _ -) را می‌پذیرد.
  • اگر پوشه‌ای با همان نام از قبل وجود داشته باشد، نصب متوقف می‌شود.
  • بعد از نصب، فایل .env را بررسی و در صورت نیاز ویرایش کنید.

اجرای پروژه

پس از نصب موفق، پروژه در پوشه‌ای با نام انتخابی شما ساخته می‌شود. کافی است به آدرس زیر در مرورگر بروید:

URL 
http://127.0.0.1/نام-پروژه

صفحه خوش‌آمدگویی Atrim را خواهید دید.

۳. ساختار پروژه

بعد از اجرای نصب‌کننده، ساختار زیر ایجاد می‌شود:

نام-پروژه/ ├── index.php # نقطه ورود اصلی ├── .htaccess # بازنویسی URL به index.php ├── .env # تنظیمات محیطی ├── Assets/ # فایل‌های استاتیک و آپلودها ├── Pages/ │ ├── header.php # هدر مشترک صفحات │ ├── footer.php # فوتر مشترک صفحات │ └── home.atrim.php # صفحه اصلی └── Core/ ├── core.php # بارگذاری تمام اجزا ├── Config/ │ ├── config.php # خواندن .env و شروع سشن │ └── message.php # پیام‌های اعتبارسنجی فارسی ├── Connection/ │ └── connection.php # اتصال PDO ├── Routes/ │ └── route.php # تعریف مسیرها ├── Functions/ │ └── functions.php # توابع کمکی و Router └── Classes/ ├── DB.atrim.php # کلاس دیتابیس ├── VH.atrim.php # کلاس اعتبارسنجی ├── SH.atrim.php # کلاس سشن └── FH.atrim.php # کلاس فایل
📌 نکته درباره پسوند .atrim.php

صفحات محتوایی با پسوند .atrim.php ساخته می‌شوند. این کار برای جدا کردن صفحات از فایل‌های سیستمی انجام شده است. هنگام تعریف مسیر فقط نام صفحه (بدون پسوند) را بنویسید.

۴. تنظیمات (.env)

تمام تنظیمات اصلی پروژه در فایل .env قرار دارد. این فایل بعد از نصب به‌صورت خودکار ساخته می‌شود:

.env 
#App Name:
APP_NAME="Atrim"
VERSION=1.0.0
APP_URL=http://127.0.0.1/Atrim

# DataBase:
DB=mysql
DB_HOST=localhost
DB_NAME=test
DB_USERNAME=root
DB_PASSWORD=""
DB_PORT=3306
DB_CHARSET=utf8mb4

#SESSION:
EXPIRE_TIME=60
LOGIN_EXPIRE_TIME=2592000

#PAGINATION:
POST_PERPAGE = 6;
کلید توضیح
APP_NAME نام اپلیکیشن
APP_URL آدرس پایه پروژه (برای تولید لینک‌ها ضروری است)
DB_* اطلاعات اتصال به دیتابیس MySQL
EXPIRE_TIME زمان انقضای سشن معمولی (ثانیه) — پیش‌فرض ۶۰ ثانیه
LOGIN_EXPIRE_TIME زمان انقضای سشن لاگین (ثانیه) — پیش‌فرض ۳۰ روز
POST_PERPAGE تعداد آیتم در هر صفحه برای متد paginate
🔒 امنیت

فایل .env حاوی اطلاعات حساس است. مطمئن شوید که از طریق وب قابل دسترسی نیست (معمولاً با .htaccess محافظت می‌شود یا خارج از public قرار می‌گیرد).

۵. مسیریابی (Routing)

مسیرها در فایل Core/Routes/route.php تعریف می‌شوند. ساختار ساده است:

Core/Routes/route.php 
<?php

$routes = [
    "/"           => "home",
    "/about"      => "about",
    "/post/:id"   => "post",
    "/user/:username/posts" => "user-posts",
];

پارامترهای داینامیک

با استفاده از :نام می‌توانید پارامترهای متغیر تعریف کنید. این پارامترها به‌صورت خودکار در صفحه استخراج می‌شوند:

Pages/post.atrim.php 
<?php
// اگر مسیر /post/:id باشد و کاربر به /post/42 برود
// متغیر $id به‌صورت خودکار در دسترس است
echo "شناسه پست: " . e($id);
✓ قوانین مسیریابی
  • کلید آرایه = مسیر URL
  • مقدار آرایه = نام فایل صفحه بدون پسوند .atrim.php
  • اگر صفحه‌ای پیدا نشود، کد ۴۰۴ برگردانده می‌شود
  • می‌توانید فایل Pages/404.atrim.php بسازید تا صفحه ۴۰۴ سفارشی نمایش داده شود

۶. صفحات

هر صفحه در پوشه Pages/ با پسوند .atrim.php قرار می‌گیرد.

ایجاد صفحه جدید

  1. فایل جدید بسازید: مثلاً Pages/about.atrim.php
  2. مسیر را در route.php اضافه کنید: "/about" => "about"
  3. محتوای HTML یا PHP خود را داخل فایل بنویسید

هدر و فوتر مشترک

فایل‌های header.php و footer.php در هر درخواست به‌صورت خودکار قبل و بعد از صفحه لود می‌شوند (توسط getHeader() و getFooter() در index.php).

index.php 
<?php
require __DIR__ . "/./Core/core.php";

getHeader();
Router();
getFooter();

۷. توابع کمکی (Helpers)

این توابع در Core/Functions/functions.php تعریف شده‌اند و در تمام صفحات در دسترس هستند.

url(string $path = "/") string

آدرس کامل بر اساس APP_URL می‌سازد.

مثال
echo url("/about");          // http://127.0.0.1/Atrim/about
echo url("posts/5");         // http://127.0.0.1/Atrim/posts/5
Assets(string $path) void (echo)

آدرس فایل‌های داخل پوشه Assets را چاپ می‌کند.

مثال
<img src="<?php Assets('images/logo.png'); ?>" alt="لوگو">
<link rel="stylesheet" href="<?php Assets('css/style.css'); ?>">
go(string $path = "/") redirect + exit

کاربر را به مسیر مورد نظر هدایت می‌کند و اسکریپت را متوقف می‌کند.

مثال
go("/login");
go("dashboard");
e(mixed $value) string (escaped)

برای جلوگیری از XSS، خروجی را با htmlspecialchars امن می‌کند. همیشه از این تابع برای نمایش داده‌های کاربر استفاده کنید.

مثال
echo e($user['name']);
<title><?= e($pageTitle) ?></title>
input(?string $key, mixed $default, string $method) mixed

خواندن داده از $_POST / $_GET / $_REQUEST.

مثال
$email = input('email');                    // از POST
$name  = input('name', 'مهمان', 'GET');     // از GET با مقدار پیش‌فرض
$all   = input();                           // کل آرایه POST
old(string $key, mixed $default, string $method) mixed

برای پر کردن مجدد فرم بعد از خطای اعتبارسنجی (مشابه Laravel old).

مثال
<input type="text" name="email" value="<?= e(old('email')) ?>">
isLogin() · mustLogin() · logOut()

توابع مرتبط با وضعیت لاگین کاربر:

مثال
if (isLogin()) {
    echo "خوش آمدید";
}

mustLogin("/login");   // اگر لاگین نباشد به /login می‌رود

logOut();              // خروج و هدایت به صفحه اصلی
J2A(string $json) · A2J(mixed $value)

تبدیل JSON به آبجکت/آرایه و برعکس (با پشتیبانی از یونیکد).

۸. کلاس DB (دیتابیس)

کلاس \Core\Classes\DB تمام عملیات دیتابیس را به‌صورت امن با PDO انجام می‌دهد. نام جداول و ستون‌ها اعتبارسنجی می‌شوند تا از SQL Injection جلوگیری شود.

insert

DB::insert(string $table, array $data)
مثال
use Core\Classes\DB;

DB::insert('users', [
    'name'  => 'محمد',
    'email' => 'test@example.com',
    'age'   => 25
]);

get

DB::get(string $table, bool $single = false, array $where = [], array $columns = ['*'])
مثال
// همه کاربران
$users = DB::get('users');

// یک کاربر با شرط
$user = DB::get('users', true, ['id' => 5]);

// فقط ستون‌های خاص
$names = DB::get('users', false, [], ['id', 'name']);

update

DB::update(string $table, array $where, array $data)
مثال
DB::update('users', ['id' => 5], [
    'name' => 'علی',
    'age'  => 30
]);
⚠ اجباری بودن شرط

آپدیت بدون شرط ($where خالی) مجاز نیست و Exception پرتاب می‌کند.

delete

DB::delete(string $table, array $where)
مثال
DB::delete('users', ['id' => 5]);

paginate

DB::paginate(string $table, int $page = 1, array $where = [], array $columns = ['*'])

صفحه بندی خودکار بر اساس مقدار POST_PERPAGE در فایل .env.

مثال
$result = DB::paginate('posts', 2);

// خروجی:
// [
//   'data' => [...],
//   'meta' => [
//      'total' => 45,
//      'per_page' => 6,
//      'current_page' => 2,
//      'last_page' => 8
//   ]
// ]

search

DB::search(string $table, string $keyword, array $columns, array $where = [], int $limit = 10)
مثال
$results = DB::search('posts', 'php', ['title', 'body'], ['status' => 'published'], 20);

register و login

DB::register() · DB::login()

متدهای آماده برای ثبت‌نام و ورود با هش امن رمز عبور (password_hash / password_verify).

مثال
// ثبت‌نام
DB::register('users', 'user@email.com', 'Secret123!', [
    'name' => 'محمد'
]);

// ورود
if (DB::login('users', 'user@email.com', 'Secret123!')) {
    go('/dashboard');
} else {
    echo 'ایمیل یا رمز اشتباه است';
}

۹. کلاس VH (اعتبارسنجی)

کلاس \Core\Classes\VH یک سیستم اعتبارسنجی کامل شبیه Laravel است که پیام‌های خطا را به فارسی برمی‌گرداند.

نحوه استفاده

مثال کامل 
use Core\Classes\VH;

$ok = VH::validation($_POST, [
    'name'     => 'required|string|min:3|max:50|persian',
    'email'    => 'required|email',
    'mobile'   => 'required|mobile',
    'password' => 'required|password:8',
    'age'      => 'nullable|integer|min:18|max:100',
], [], [
    'name'     => 'نام',
    'email'    => 'ایمیل',
    'mobile'   => 'موبایل',
    'password' => 'رمز عبور',
    'age'      => 'سن',
]);

if (VH::fails()) {
    // نمایش خطاها
    foreach (VH::$message as $field => $errors) {
        foreach ($errors as $error) {
            echo "<p>" . e($error) . "</p>";
        }
    }
} else {
    // داده‌ها معتبر هستند
}

۱۰. کلاس SH (سشن)

کلاس \Core\Classes\SH مدیریت سشن را ساده می‌کند.

متد توضیح
SH::make($name, $value) ایجاد سشن (فقط اگر از قبل وجود نداشته باشد)
SH::show($name) خواندن مقدار سشن
SH::has($name) بررسی وجود سشن
SH::delete($name) حذف سشن
SH::flash($name) خواندن و بلافاصله حذف (برای پیام‌های یک‌بار مصرف)
SH::ex($name, $login) بررسی و اعمال انقضای زمانی سشن
مثال
use Core\Classes\SH;

SH::make('flash_message', 'عملیات با موفقیت انجام شد');
echo SH::flash('flash_message');   // نمایش و حذف

۱۱. کلاس FH (مدیریت فایل)

کلاس \Core\Classes\FH برای کار با فایل‌های داخل پوشه Assets طراحی شده است.

متد توضیح
FH::exists($path)بررسی وجود فایل
FH::read($path)خواندن محتوای فایل
FH::write($path, $content)نوشتن در فایل
FH::append($path, $content)افزودن به انتهای فایل
FH::delete($path)حذف فایل
FH::extension($path)پسوند فایل
FH::name($path)نام فایل
FH::readJson($path)خواندن فایل JSON به‌صورت آرایه
FH::writeJson($path, $data)نوشتن آرایه به‌صورت JSON
📌 مسیر پایه

تمام مسیرها نسبت به پوشه Assets/ در نظر گرفته می‌شوند. مثلاً FH::read('data/config.json') معادل Assets/data/config.json است.

۱۲. احراز هویت

فریمورک سیستم لاگین آماده‌ای دارد که با ترکیب کلاس‌های DB و SH کار می‌کند.

ثبت‌نام

مثال
try {
    DB::register('users', input('email'), input('password'), [
        'name' => input('name')
    ]);
    go('/login');
} catch (InvalidArgumentException $e) {
    echo e($e->getMessage());  // مثلاً: این ایمیل قبلاً ثبت شده است
}

ورود

مثال
if (DB::login('users', input('email'), input('password'))) {
    go('/dashboard');
} else {
    echo 'اطلاعات ورود نادرست است';
}

محافظت از صفحات

در ابتدای صفحه محافظت‌شده
mustLogin('/login');   // اگر لاگین نباشد ریدایرکت می‌شود

$user = \Core\Classes\SH::show('user');
echo 'سلام ' . e($user['name']);

۱۳. آپلود فایل

متد DB::upload برای آپلود امن فایل‌ها طراحی شده است.

DB::upload(array $file, string $path = '', array $allowed = [...], int $maxSize = 2097152)
  • $file: آرایه فایل از $_FILES['field']
  • $path: زیرپوشه داخل Assets (مثلاً images/avatars)
  • $allowed: پسوندهای مجاز (پیش‌فرض: jpg, jpeg, png, webp, pdf)
  • $maxSize: حداکثر حجم به بایت (پیش‌فرض ۲ مگابایت)
مثال
try {
    $url = DB::upload($_FILES['avatar'], 'avatars', ['jpg', 'png', 'webp'], 1048576);
    // $url = آدرس کامل فایل آپلود شده
    echo $url;
} catch (Exception $e) {
    echo e($e->getMessage());
}

۱۴. قوانین و نکات مهم

✅ بایدها
  • همیشه از تابع e() برای نمایش داده‌های کاربر استفاده کنید.
  • قبل از هر عملیات دیتابیس، اعتبارسنجی را با VH انجام دهید.
  • صفحات محافظت‌شده را با mustLogin() شروع کنید.
  • مقدار APP_URL را در .env دقیقاً مطابق آدرس واقعی پروژه تنظیم کنید.
  • برای پارامترهای مسیر از نام‌های معنادار استفاده کنید (:id، :slug و ...).
❌ نبایدها
  • هرگز داده خام کاربر را بدون e() چاپ نکنید.
  • آپدیت یا حذف بدون شرط انجام ندهید (فریمورک خودش جلویش را می‌گیرد).
  • فایل .env را در گیت‌هاب یا مکان عمومی قرار ندهید.
  • از نام‌های غیرمجاز برای پروژه (فاصله، کاراکتر خاص) استفاده نکنید.

جریان درخواست (Request Lifecycle)

  1. درخواست به index.php می‌رسد (از طریق .htaccess)
  2. core.php تمام فایل‌های Config، Routes، Classes و Functions را لود می‌کند
  3. اتصال دیتابیس برقرار و به کلاس DB تزریق می‌شود
  4. سشن لاگین در صورت وجود بررسی و تمدید می‌شود
  5. getHeader() هدر را لود می‌کند
  6. Router() مسیر را پیدا کرده و صفحه مربوطه را اجرا می‌کند
  7. getFooter() فوتر را لود می‌کند
